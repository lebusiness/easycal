# ТЗ: личный трекер калорий (PWA, MVP)

Сделай одностраничное веб-приложение (PWA) — трекер калорий для одного человека. Язык интерфейса — русский. Mobile-first. Без бэкенда и авторизации: всё работает в браузере, данные хранятся локально на устройстве.

## Стек
- Vite + React + Tailwind CSS
- Dexie.js (IndexedDB) — хранение дневника и своих продуктов
- html5-qrcode — сканирование штрихкодов камерой
- vite-plugin-pwa — manifest + service worker, чтобы приложение ставилось на телефон и открывалось офлайн

## Экраны

### 1. Дневник (главный)
- Сверху дата (по умолчанию сегодня) и стрелки ◀ ▶ для переключения дней.
- Список съеденного за день: название, граммы, ккал. Запись можно удалить.
- Крупный итог дня: калории и Б/Ж/У.
- Кнопка «+ Добавить еду».

### 2. Добавление еды
- Поле поиска по названию + кнопка «Сканировать штрихкод».
- Результаты списком: название, бренд (если есть), ккал на 100 г.
- При выборе продукта: ввод граммов (по умолчанию 100), живой пересчёт КБЖУ на порцию, кнопка «Добавить в дневник».
- Если ничего не нашлось — кнопка «Ввести вручную»: форма (название, ккал, белки, жиры, углеводы на 100 г, опционально штрихкод). Такой продукт сохраняется в «Мои продукты» и в дальнейшем находится и поиском, и по штрихкоду.

## Источники данных (каскад)

### Поиск по названию
1. Сначала искать в «Моих продуктах» (IndexedDB, по подстроке, без учёта регистра).
2. Затем — Open Food Facts search-a-licious:
   `GET https://search.openfoodfacts.org/search?q={запрос}&page_size=10&langs=ru`
3. Если он вернул ошибку — fallback на legacy-поиск:
   `GET https://ru.openfoodfacts.org/cgi/search.pl?search_terms={запрос}&search_simple=1&action=process&json=1&page_size=10`
4. В выдаче показывать сначала «Мои продукты», ниже — результаты из Open Food Facts.

### Штрихкод
1. Сначала искать штрихкод в «Моих продуктах».
2. Затем: `GET https://world.openfoodfacts.org/api/v2/product/{barcode}.json`
   - `status = 1` → взять `product_name` (лучше `product_name_ru`, если есть), `brands` и нутриенты.
   - `status = 0` → сообщение «Продукт не найден» и сразу открыть форму ручного ввода с уже подставленным штрихкодом.

### Поля нутриентов Open Food Facts (на 100 г)
`nutriments["energy-kcal_100g"]`, `nutriments.proteins_100g`, `nutriments.fat_100g`, `nutriments.carbohydrates_100g`.
Если какого-то поля нет — показать прочерк и дать дозаполнить вручную перед добавлением в дневник.

## Сканер штрихкодов
- html5-qrcode, распознавать только форматы EAN_13 и EAN_8.
- Задняя камера: `facingMode: "environment"`.
- Открывается по кнопке, после успешного скана камера закрывается.
- Если пользователь не дал доступ к камере — понятное сообщение, а не падение приложения.

## Модель данных (Dexie)
- `diary`: id, date (строка YYYY-MM-DD), name, grams, kcal, protein, fat, carbs
- `myProducts`: id, name, barcode (опционально), kcal100, protein100, fat100, carbs100

## В этой версии НЕ нужно
Авторизация, облачная синхронизация, графики, цели по калориям, фото еды, рецепты.

## Критерии готовности
- Сканирую штрихкод → вижу КБЖУ продукта → указываю граммы → запись в дневнике, итоги дня пересчитались.
- Ищу «творог» по названию и добавляю в дневник.
- Создаю продукт вручную — потом он находится и поиском, и по своему штрихкоду.
- Данные не пропадают после перезагрузки страницы и работают офлайн (кроме онлайн-поиска в Open Food Facts).
- Приложение устанавливается на телефон как PWA.

## Требования к коду
- Сразу рабочий код, без заглушек и TODO.
- Любая ошибка сети или API не должна ронять приложение: показывай понятное сообщение и предлагай ручной ввод.
- Все запросы к API — с таймаутом и индикатором загрузки.
