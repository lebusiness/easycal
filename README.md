# Трекер калорий (PWA)

Личный дневник питания: одностраничное приложение без бэкенда. Все данные хранятся локально в браузере (IndexedDB), приложение ставится на телефон и работает офлайн — кроме онлайн-поиска в Open Food Facts.

## Запуск

Нужен PostgreSQL (macOS: `brew install postgresql@17 && brew services start postgresql@17`).

```bash
npm install
cd server && npm install && cd ..

npm run server     # API: http://localhost:7347 (база calorie_tracker создастся сама)
npm run dev        # фронтенд: http://localhost:7345 (в другом терминале)
```

Продакшен: `npm run build`, затем `npm run server` — Express сам раздаёт собранный фронтенд из `dist/` на том же порту 7347 (один origin, без CORS).

Переменные окружения сервера: `DATABASE_URL` (по умолчанию `postgres://localhost:5432/calorie_tracker`), `JWT_SECRET` (обязательно смените для продакшена), `PORT` (7347).

Порты намеренно нестандартные (7345 dev, 7346 preview), чтобы не пересекаться с 3000/5173/8080 и т. п. — поменять можно в `vite.config.js` (`server.port` и `preview.port`). Если порт вдруг занят, Vite сам возьмёт следующий свободный и напишет его в консоли.

## Проверка на телефоне

Камера (сканер штрихкодов) работает только в безопасном контексте — на `localhost` или по HTTPS. Чтобы протестировать с телефона в локальной сети:

```bash
npm run dev:https   # HTTPS с самоподписанным сертификатом (@vitejs/plugin-basic-ssl)
```

Откройте `https://<IP-компьютера>:7345` на телефоне и согласитесь с предупреждением о сертификате. Для постоянного использования проще задеплоить `dist/` на любой статический хостинг с HTTPS (Netlify, Vercel, GitHub Pages) и установить как PWA («Добавить на главный экран»).

## Что умеет

- Аккаунты и данные на сервере (Express + PostgreSQL): регистрация и вход по почте и паролю без писем, пароль — bcrypt-хэшем, сессия — JWT на 30 дней. Все записи хранятся в Postgres под аккаунтом; IndexedDB работает как локальное зеркало — мгновенные чтения и офлайн-просмотр последнего состояния (изменения офлайн недоступны).

- Дневник по дням с приёмами пищи (по умолчанию Завтрак/Обед/Ужин/На ночь): приёмы можно переименовывать, добавлять, удалять и менять порядок; секции сворачиваются; у записей — время добавления.
- Цели Б/Ж/У на день (ккал считаются автоматически по 4/9/4) с прогресс-барами вверху дневника.
- Добавление еды: поиск по всем продуктам (свои + избранное + Open Food Facts: search-a-licious с fallback на legacy-поиск, транслит для латинских брендов, клиентское ранжирование) и сканирование штрихкодов EAN-13/EAN-8 камерой (плюс ручной ввод цифр кода).
- Вкладки «Частые» / «Избранное» / «Свои»: частые считаются по истории дневника и учитывают приём пищи (на ночь — сначала то, что вы едите на ночь); избранное — звёздочкой или из карточки продукта.
- Свои продукты: название, Б/Ж/У (ккал автоматически), описание и штрихкод опционально.
- В карточке любого продукта БЖУ можно отредактировать (ккал пересчитаются): добавить разово, сохранить в избранное в изменённом виде или «запатчить» — продукт из базы всегда будет открываться с вашими значениями.
- Выбор порции в граммах с живым пересчётом КБЖУ.
- Ошибки сети не роняют приложение: показывается сообщение с кнопками «Повторить» / «Ввести вручную». Все запросы — с таймаутом 8 секунд и индикатором загрузки.

## Деплой на VM (Яндекс Облако)

Предпосылки: Ubuntu VM с публичным IP, домен (A-запись) уже указывает на этот IP, в группе безопасности открыты порты 22, 80 и 443. Код лежит на GitHub.

```bash
ssh <user>@<ip>
git clone https://github.com/<you>/<repo>.git easycal
cd easycal
sudo DOMAIN=easycal.ru EMAIL=you@example.com bash deploy/setup.sh
```

Скрипт сам ставит Node.js 22, PostgreSQL, nginx и certbot, создаёт базу и секреты (`/etc/calorie-tracker.env`), собирает фронтенд, заводит приложение как systemd-сервис `calorie-tracker`, настраивает nginx (включая прокси к Open Food Facts) и выпускает HTTPS-сертификат Let's Encrypt с автопродлением. После него открывайте `https://easycal.ru` — PWA ставится на телефон через «Добавить на главный экран». Скрипт идемпотентный: можно запускать повторно.

Обновление после `git push`:

```bash
cd easycal && bash deploy/update.sh
```

Полезное: `journalctl -u calorie-tracker -f` — логи, `systemctl status calorie-tracker` — статус.

## Безопасность

- **Перебор паролей**: вход/регистрация — 20 попыток с IP за 15 минут (Express) + зона 30 r/m в nginx; пароли — bcrypt.
- **Флуд/DoS**: общий лимит API 240 req/мин с IP (Express) + 20 r/s и лимит соединений в nginx; тело запроса ≤ 200 КБ. От настоящего распределённого DDoS это не спасёт — при необходимости включите защиту на уровне Яндекс Облака или поставьте впереди Cloudflare.
- **Взлом**: SQL — только параметризованные запросы и вайтлист таблиц; XSS — React-экранирование + CSP/HSTS/nosniff/frame-ancestors через helmet; сервер отказывается стартовать в проде с дефолтным JWT_SECRET; приложение слушает только 127.0.0.1 за nginx; fail2ban защищает SSH.
- **Стирание данных**: ежедневный pg_dump в 03:30 в `/var/backups/calorie-tracker` (хранится 14 дней), восстановление: `zcat backup.sql.gz | sudo -u postgres psql calorie_tracker`. Плюс ручной экспорт CSV/JSON на экране «История». Данные пользователей изолированы по `user_id`, у роли БД нет суперправ.

## CORS и Open Food Facts

У поисковых endpoint'ов Open Food Facts проблемы с CORS: search-a-licious не отдаёт `Access-Control-Allow-Origin`, а legacy-поиск блокирует прямые запросы из браузера (503). Штрихкод-API (`world.openfoodfacts.org/api/v2`) при этом отдаёт корректный `Access-Control-Allow-Origin: *`.

Поэтому:

- **Локально** (dev и preview) все запросы к OFF идут через прокси Vite (`/off-search`, `/off-ru`, `/off-world` → см. `vite.config.js`). Работает автоматически, ничего настраивать не нужно.
- **Деплой**: в репозитории лежат готовые `netlify.toml` и `vercel.json` — они включают такие же rewrite'ы на хостинге и выставляют `VITE_OFF_PROXY=1` на сборке, чтобы приложение ходило через них. На хостинге без rewrite'ов (например, GitHub Pages) приложение ходит на OFF напрямую: штрихкоды работают всегда, а поиск — только если OFF починит CORS (каскад и ручной ввод при этом остаются).

Учтите лимит OFF на поиск (~10 запросов в минуту с IP): при частых запросах сервер начнёт отвечать 429/503 — приложение покажет ошибку с кнопкой «Повторить».

## Стек

Vite + React + Tailwind CSS 4, Dexie.js (IndexedDB), html5-qrcode, vite-plugin-pwa.
